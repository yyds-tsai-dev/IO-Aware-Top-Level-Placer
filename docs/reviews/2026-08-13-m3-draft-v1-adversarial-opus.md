## F2 [BLOCKER] §3.1/§5.2:`κ_ft>1` 時 objective 對 `λ−1` 的係數為負——C2 掃描含「獎勵 crossing」的臂

**被攻擊原文(§0 Q4):**「`κ_ft` 大於 1 = 額外加罰 feed-through」。

**推導:** ReLU 都啟用時
`L_IO+κ_ft·L_FT = w_e[(λ_e−1) + κ_ft(R_e−λ_e+1)] = w_e[(1−κ_ft)(λ_e−1) + κ_ft·R_e]`。
`κ_ft=2` ⇒ `−w(λ−1)+2wR`;`κ_ft=4` ⇒ `−3w(λ−1)+4wR`。**C2 的 {2,4} 兩臂在梯度上主動獎勵 net 觸及更多 region**,與 E3 直接對撞。這不是實驗會發現的意外,是可先驗排除的。`κ_ft<1` 也不乾淨:對 FT-active 的 net,IO 係數被稀釋成 `(1−κ_ft)`,而換來的 FT 係數 `∂R/∂q_k = g_k(D_k−R)/N_e` 在飽和區只有 **0.035**(β=0.5、Λ=2、D=2、q=1;β=0.25 時 7e−4)——**用 1 的 IO 壓力換 0.035 的 FT 壓力**。

**修法:** FT 項內的 `(λ_e−1)` 改成 **detach / 用 evaluator 每 callback 給的 hard `Λ_e−1`**:
`L_FT = Σ_e w_e·ReLU(R_e − (Λ̄_e−1))`,`Λ̄` 為凍結常數(與 `home_e` 同一個事件點更新,§5.3 的順序不變)。於是
`c_{e,k} = w_e[1[λ_e>1] + κ_ft·1[R_e>Λ̄_e−1]·g_{e,k}(D_{e,k}−R_e)/N_e]`,**沒有 −1 項、IO 壓力零損失、`κ_ft` 是純加法旋鈕、任意 κ_ft>0 都合法**。代價是失去「`κ_ft=1` 恆等於 `max(λ−1,R)`」這句話——它本來就只是修辭,而且 §3.2 理由 5 用它當賣點是本末倒置。(注意:此修法**不**單獨解決 F1;實測 `WA/hardLam` 在 τ_rel=0.03、β=0.5 是 25,986 = 7.68× 真值,更糟。F1 與 F2 必須一起修。)

## F4 [MAJOR] §4.2:S7 內部有三套互斥的 routing 模型,且懲罰式是 0 次齊次、softplus 永不熄火

**被攻擊原文(§4.2):**「soft 需求 `D_ab` 的算法(**與 §2.2 的 routing 模型一致**,且 chunk-safe)」、§5.2「當 `L_cap` 梯度為 0 時保持不變(項本來就惰性)」、R6「hinge 在啟用初期梯度恆 0」。

1. **模型自相矛盾:** `Q[h,k]·P[h,k,(a,b)]` 是「每個 touched region 各自從 home 拉一條最短路」= **星形模型**,正是 §3.2 花整節否掉的 S4a 幾何(對鏈狀 net 重複計費 1.2–1.8 倍)。而 L10 要拿來校驗的 `boundary_pair_demand` 又是第三套(MST + L 形 walk,`ioplace/evaluator_ref.py:70`)。一份文件三把尺。
2. **`C_ab` 是 0 次齊次:** `C_ab = ν·ℓ_ab·(ΣD/Σℓ)` ⇒ `(D_ab−C_ab)/C_ab` 對「所有 D 同比例縮放」不變。此項對**總需求下降完全無感**,只管形狀;而且對冷邊界灌需求可以抬高 `ΣD` 進而放寬所有邊界——與 S2 直接對打。跨 callback 重算 `C_ab` 則變成「你壓多少我縮多少」的追逐。
3. **softplus 永不熄火:** `D_ab ≥ 0` ⇒ 參數 `(D_ab−C_ab)/C_ab ≥ −1` ⇒ `σ(z) ≥ σ(−1) = 0.269`。**梯度的下界是最大值的 27%**,不存在「初期梯度恆 0」的情形。⇒ §5.2 的「零梯度凍結」是死碼,R6 的風險描述是錯的,而 `λ_cap = κ_cap·g_comb/g_cap` 會被一個不小但持續漂移的分母牽著跑;而且 §5.2 寫的上限「`ρ_max` 乘 WL 梯度 L1」與 `λ_cap`(權重)量綱不符,mechanical executor 會實作錯。
4. **ν=1.5 未定錨:** flat 的 max/mean 已是 2.84 ⇒ 此項在 baseline 就重度啟用,不是「防止退化」而是「強推一個幾何上未必可達的分布」。

**修法(若 F3 之後 S7 仍要做):** (a) `D_ab` 改用與 §2.2 同模型的量(Steiner 樹邊 → 邊界對),或誠實改名為 star-demand 並在 §2.3 撤回對星形的否決理由;(b) `C_ab` 固定為 **flat baseline 的實測值 × ν**,`ν ≥ 該 case flat 的 max/mean`,一次算完全程凍結;(c) softplus 換成 `ReLU(·)²` 或 `softplus(z/θ)`,θ≤0.1;(d) `λ_cap` 上限明確寫成「貢獻上限:`λ_cap·‖∇L_cap‖₁ ≤ ρ_max·‖∇WL‖₁`」,凍結規則改成 `g_cap < 0.01·g_comb`。

## F8 [MAJOR] §5.2:`ratio` 改量合併項的**理由**寫反了,後果是 κ_ft 只能轉方向不能加壓

**被攻擊原文:**「**量合併項的梯度**(不是只量 `L_IO`);否則 `κ_ft` 會被正規化抵銷掉」。

`λ_io = ρ_io·ratio_ema`,`ratio_ema = ‖∇WL‖₁/‖∇(L_IO+κ_ft L_FT)‖₁` ⇒ 實際施加的 IO+FT 梯度範數 ≈ `ρ_io·‖∇WL‖₁`,**與 κ_ft 無關**。是這個選擇把 κ_ft 的量級效應抵銷掉;只量 `L_IO` 才會讓總壓力隨 κ_ft 上升。兩種都可以,但理由必須寫對,且會決定 C2 掃描的意義:目前是 **iso-pressure 旋轉方向**的掃描,配合 F2 的稀釋效應,κ_ft 對 FT 的淨作用是有界且方向不明的。

**修法:** 在 §5.2 明寫「合併正規化 = iso-pressure 掃描,κ_ft 只改方向」;若 T6 想看到 FT 壓力真的上升,需改用 `λ_io` 由 `L_IO` 定錨、FT 額外加 `κ_ft` 的形式(與 F2 的修法天然相容)。

## F10 [MAJOR] §3.1 公式的兩個數值陷阱(會直接產生 NaN)

**被攻擊原文:** `c_{e,k} = w_e[…κ_ft·1[R>λ−1]·((D−R)·a_{e,k}/(q_{e,k}·N_e) − 1)]`、`R_e = M_e/max(N_e,ε)`。

1. **`a_{e,k}/q_{e,k}` 是 0/0。** 我的獨立推導確認 `∂R/∂q_{e,k} = g_{e,k}(D_{e,k}−R_e)/N_e`,`g = exp((D−ecc_max)/β)`,`a/q` 只是它的一種寫法。但 `q_{e,k}` 對絕大多數 (e,k) 恰好是 **0**:`p` 在 fp32 下溢 ⇒ `ℓ=log1p(−0)=0` ⇒ `S=0` ⇒ `q=−expm1(0)=0`(`ioplace/ops/io_term.py:198`)。**必須寫成 `g_{e,k}/N_e`**,否則 backward 全張量 NaN。
2. **`max(N_e,ε)` 會靜默壓掉 R。** 由於用的是 per-home 的全域 `ecc_max`,`N_e` 的合法量級是 `e^{−ecc/β}`:β=0.5、ecc=6 → 6.1e−6;β=0.25、ecc=6 → 3.8e−11;K=32、β=0.1 → e^{−100}。任何 ε ≳ 1e−12 都會讓「所有 region 都靠近 home」的 net 的 R 被腰斬。**指定 `ε=0` + `torch.where(N>0, M/N, 0)`**,並加一條 K=32、β=0.1 的最壞情況測試(L6 的「fp64 就好」結論方向對,但守衛寫錯了)。

順帶確認 §3.1 的「零額外 chunk pass」**成立**:`_IoFn` 的四趟結構(`ioplace/ops/io_term.py:181-279`:FWD-1 `softmax_stats`、FWD-2 累 `S_c/lam`、BWD-1 算 `A`、BWD-2 scatter)中,`N_e/M_e` 可在 FWD-2 同趟累加,`R_e/N_e` 存進 `ctx`,BWD-1/BWD-2 重算 `S_c` 時即可就地組出 `c_{e,k}`,`D[home,lo:hi]` 是 (E,c) gather,在既有契約內。可省一個累加器:backward 只需要 `N_e` 與 `R_e`,`M_e` 用完即棄 ⇒ 30M net 時常駐 2×(E,)fp64 ≈ 576 MB(G6 的 8 GB 內,但要寫進 §2.5 的記憶體帳)。

## F11 [MINOR] §2.2/§2.4:上界/下界語意混用;Λ≥4 的 `ft_rg` 不是「被穿越 region 數」

- §2.2 說「`io_rg`/`ft_rg` 皆為上界」,§2.4 L1 說「`ft_rg` 只是**下界**」。兩者分別相對「RG 模型內的精確 Steiner」與「真實幾何可實現路徑」,必須各自標明參照物。
- 更實質的問題:Λ≥4 用 metric-closure MST 時,`FT := ST̂−(Λ−1)` 是**由恆等式定義**的數,不是 `|V(T)\terminals|`——最短路在 closure 上展開會共用中間節點,distinct region 數會少於 `ST̂−(Λ−1)`。而 evaluator 的 `ft_mst` 量的正是 distinct(`ioplace/evaluator_ref.py:113` `len(passed - pin_regions)`),spec §2 也是 distinct。
- **修法(T1 驗收條件):** Λ≥4 時把 MST/DW 的解**展開成 `G_R` 上的實際子樹**,`ST` 取該樹的邊數、`ft_rg` 取該樹的非 terminal 頂點數。這樣兩者同時來自一棵可行樹,恆等式**精確**成立,且 `io_rg` 仍是可行上界。

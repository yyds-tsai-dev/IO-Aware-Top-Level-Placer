# GGR/GAMER trial on the current physical benchmarks

## Current conclusion

Xplace GGR builds and executes successfully in an isolated environment. It is now an executable routing candidate, but it has not passed the requirements for replacing OpenROAD in the feedback loop. The first small-case trial exposes a physical-connectivity interoperability problem. Tile trials are in progress; no large-case speedup or congestion improvement is established yet.

The implementation uses Xplace revision `49cf66bc75ba9908f145bb6686f03cde692367cf`, with its GPU maze routing enabled by `rrrIters=1`. Pattern-only trials use zero reroutes. The build leaves the active DREAMPlace and OpenROAD installations untouched. Dependencies, source patches, build failures and successful build receipts are preserved under `results/grt_fast_20260915/ggr_build/`.

GGR's 48 × 48 grid marks 35 of 579 parser nets as requiring no route. Sixteen are also empty in the OpenROAD reference; an additional 19 become local to a coarse GCell and have no selected segments. The GGR pin-access model accounts for them, but this is not evidence of physical connectivity. An earlier 512 × 512-grid smoke had 563 selected routes and 16 empty routes; those counts must not be substituted for the final 48 × 48 trial.

The GGR grid differs from OpenROAD's 47 × 48 grid. Exact grid boundaries and layer metadata are preserved. Metrics project the chosen physical wires onto the same OpenROAD resource grid. This projection does not recover missing pin-access wires or certify routability.

### OpenROAD interoperability

The first segment import failed with `GRT-0258` because Xplace removes DEF identifier escaping. A checked, injective mapping restores exact original names without changing geometry. Importing the restored segments gets past that error, but OpenROAD then rejects the clock with `GRT-0262 Net clk has disconnected segments`.

The exported graph becomes connected under GGR's equivalence between access candidates of the same pin. OpenROAD's selected-segment connectivity check does not accept that representation. No artificial bridging wires were added. Native guide import is a separate integration route under investigation; guide acceptance alone would not establish physical connectivity or detailed-routing quality.

## Common congestion evaluator

`src/ioplace/route_eval/common_grt.py` measures unique wire-edge occupancy within each net and layer, then sums distinct nets using int64 counters. It validates syntax, coordinates, rectilinear wires, adjacent vias and layer policy. Duplicate branches do not inflate demand. Nonpreferred wires face zero capacity on that direction. Vias are counted but contribute no edge demand; physical-pin coverage remains a separate requirement.

The baseline extractor initializes OpenROAD routing resources without running global-route optimization. It removes only existing `GCELLGRID` declarations from an owned DEF copy, verifies the retained bytes, initializes the correct block and pin-access adjustments, and exports empty-routing capacity plus fixed obstruction usage. Original inputs remain intact.

For GCD, the common evaluator reproduces native OpenROAD edge demand 3,572, resource count 117,992 and zero overflow. It also reproduces the existing IO and selected-wire metrics. For tile, the empty capacity arrays are identical between the original and stalled placements. Their effective resource count is 7,871,705, versus 7,872,067 reported by native FastRoute, a difference of 362. OpenDB's nominal capacity and clamped reductions cannot represent all native pin-access capacity increases. Its uint8 storage is another documented precision limit. Therefore tile common overflow is a shared proxy, not an asserted reproduction of native overflow.

Thirteen targeted evaluator tests pass, including per-net union, layer separation, fixed usage, nonpreferred wires, malformed geometry, duplicate names, boundary handling, generic layer-name via adjacency and demand above 255. Together with bounded-routing tests, 25 tests pass. Original experiment scripts remain preserved with their original source hashes; the reusable evaluator is now in the package.
